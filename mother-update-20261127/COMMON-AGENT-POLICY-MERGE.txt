모든 기관과 배포PC의 공통 대화·실행 지침 병합 후보

기존 AGENTS.md/CLAUDE.md와 기관 자료를 보존해 의미 단위로 병합한다. 이 문서만으로 설치 파일을 덮어쓰거나 실행 권한을 확대하지 않는다.
1. 롱텀 업무 시작마다 Aside 스킬을 읽고 실제 앱 연결/열린 탭/지정 계정·프로필/기관/수급자/미저장 상태를 확인한다. 화면에서 읽을 수 있는 사실을 사용자에게 대신 읽게 하지 않는다. 재로그인 후 새 탭을 다시 바인딩한다. 다른 작업의 로그인·미저장 편집은 보존한다.
2. 필요한 질문 전체를 번호 목록으로 먼저 안내하고 현재 질문 하나만 묻는다. 답변 후 다음으로 넘어가며 이미 확정된 답과 같은 범위 승인을 반복하지 않는다. 새 질문은 목록 추가를 알린다. 응답 맨 마지막에 현재 미답변 질문 하나를 쉬운 말로 다시 표시하며 그 뒤에는 다른 내용을 붙이지 않는다. 진행 지시를 모호한 필수 사실의 답변으로 자동 바꾸지 않는다.
3. 계획서 작성 요청은 초안/검토만 명시 제한하지 않았다면 자료 확인→LT 입력·저장→독립 재조회 대조까지 진행한다. 기존본 보존/수정 충돌, 미해결 사실, 통보/unknown 등 실제 차단을 우회하지 않는다. 통보·삭제·인쇄는 별도 범위다.
4. 새 레코드와 신규 계약을 구분한다. 신규는 실제 첫 제공일, 연속은 이전 종료일 다음 날, 갱신은 새 인정 시작일을 적용한다. 작성일은 별도다. 명시적 추가 작성은 creationIntent와 보존 번호 집합을 검증하며 같은 성공 요청/unknown 보호를 유지한다.
5. 기관 전용 작성 기준은 기관별 비공개 설정에서 명시적으로 읽고 실제 로드 증거를 남긴다. 소제목/형식은 해당 기관의 채택 기준에 따른다. 실제 체크·도움 단계·평가 판정·계약 시간으로 작성하며 미확인을 정상/자립으로 만들지 않는다. CIST 0/빈 답안만으로 검사 실시/정상/약복용을 단정하지 않는다. 실제 입력란 한도와 1회 시간 합계를 대조한다. 특정 기관의 시간·가족관계·동의값·문장·다섯 소제목을 모든 기관의 사실로 강제하지 않는다.
6. 결과평가 6-1 요청은 명시 제한이 없다면 업무데스크 게시와 독립 재조회까지 진행한다. 검토완료는 사용자 직접 수행한다. LT 저장·통보 권한으로 확대하지 않는다.
7. 종료/정리/인계는 Codex용과 Claude Code용 두 문서를 함께 작성한다. 완료/검증/남은 일/다음 단계/실행 경계는 일치시키며 도구별 시작 방법만 구분한다. 공통 개선사항은 마더 누적 목록에 연결한다.
8. 배포PC 보완은 기존 서버 API를 우선 준수한다. 공용 서버 코드·설정·DB·발행 개인키·관리 인증을 각 PC에 요구하지 않는다. 마더 원본 검토→가상/시험PC 검증→서명된 동일 버전 배포 순서를 지킨다. 로컬 테스트와 정식 배포를 구분하고 PC별 로컬 잠금만으로 전PC 동시 쓰기가 보호된다고 가정하지 않는다.
9. 테스트 건 사용자의 직접 삭제/정리는 사용자 보고와 직접 검증을 구분한다. 완료/unknown 이력을 지우거나 테스트를 자동 재생성하지 않는다.

10. 같은 계획의 결과평가는 서비스기간이 일부/전체 겹치거나 시작/종료가 달라도 그 사실만으로 중복 차단하지 않는다. 승인한 전체 계획기간을 유지하고 같은 평가일/차수 및 저장불명 보호를 별도로 검증한다. 확인된 답을 재질문하지 않는다.

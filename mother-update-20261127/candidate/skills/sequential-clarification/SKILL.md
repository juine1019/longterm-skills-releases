# 공통 확인 질문

## 항상 적용하는 문제 해결 절차

모든 롱텀 업무 스킬을 시작할 때 이 스킬을 함께 읽고 작업이 끝날 때까지 적용한다. 서식 입력에 필요한 질문뿐 아니라 궁금한 점, 이해되지 않는 지시, 자료 간 모순, 예상과 다른 결과, 기술 오류, 해결되지 않는 문제, 다음 단계의 판단·조치에 관한 질문도 포함한다.

이런 사항을 발견하면 Codex가 먼저 사용자에게 질문해 답을 찾는다. 이미 받은 답과 확인된 자료를 짧게 살펴 질문에 포함하고, 사용자에게 물어볼 필요가 있는지 혼자 추측하며 질문을 미루지 않는다. 문제나 오류를 상태 보고만 하고 끝내거나, 원인·조치를 임의로 확정하거나, 같은 실패를 반복하지 않는다. 사용자에게 보이는 현상과 확인한 내용, 답이 필요한 이유를 쉬운 말로 설명하고 아래 순서로 질문한다. 기술 오류라도 사용자가 구현 지식을 알아야 하는 질문 대신 실제 현상·의도·선택 등 답할 수 있는 한 항목을 묻는다.

답변을 반영해 허용된 범위에서 해결하고 결과를 확인한다. 해결되지 않으면 현재까지 확인한 내용을 바탕으로 다음 질문 하나를 이어간다. 새 정보가 생기면 남은 질문 목록을 갱신한다. 오류가 난 쓰기 작업은 결과를 확인하기 전 재실행하지 않으며 기존 업무의 중단·unknown·점유 보호를 지킨다.

정확한 답변을 얻고 누락·중복 질문을 줄이기 위해 다음 절차를 사용한다.

1. 현재 대화와 확인 가능한 자료를 먼저 읽는다. 이미 답했거나 근거로 확정된 내용은 질문에서 제외한다. 필요한 사실·선택만 묻고 불필요한 확인 질문을 만들지 않는다.
2. 추가 질문이 필요하면 현재 필요한 질문 전체를 번호 목록으로 먼저 보여준다. 이어서 첫 번째 미답변 질문 하나만 묻는다. 목록의 나머지 질문까지 한꺼번에 답하도록 요구하지 않는다.
3. 한 번의 질문은 하나의 결정이나 사실만 요청한다. 예를 들어 동의자·방법·날짜·최종확인자를 한 질문에 묶지 않는다. 질문 도구를 쓰더라도 활성 질문은 한 개만 제시한다.
4. 답변을 받으면 해당 항목을 반영하고 다음 미답변 질문 하나로 넘어간다. 사용자가 여러 항목을 자발적으로 답하면 모두 반영하고 남은 항목만 묻는다. 명확한 답은 재확인하지 않는다.
5. 새 질문이 생기면 목록에 추가됐음을 알리고 남은 질문 목록을 갱신한다. 앞선 답변으로 불필요해진 질문은 제외한다. 의존 관계가 바뀌면 순서를 조정한 이유를 짧게 알린다.
6. 답변이 필요한 작업은 기다리되, 답변과 무관하게 진행할 수 있는 자료 확인·정리는 계속한다. 질문에 답하지 않았다는 이유로 승인이나 사실을 추정하지 않는다.

사용자가 현재 작업의 질문 방식을 명시하면 그 지시를 우선한다. 이 절차는 기존 업무의 실행 권한·저장·통보·점유 보호를 바꾸지 않는다.

## 기관별 상시 기준 재사용

기관별로 명시적으로 확인된 상시 기준과 이번 건의 답변을 구분해 재사용한다. 상시 기준에는 실제 사용자 발언과 적용 기관·범위를 남기고, 현재 대상 이름·작성일 등은 해당 건의 값으로 산정한다. 현재 사실과 충돌하거나 범위가 불명확할 때만 질문 목록에 추가한다. 한 기관의 동의자·동의방법·동의일·최종확인자 값을 다른 기관의 공통 기본값으로 복제하지 않는다.

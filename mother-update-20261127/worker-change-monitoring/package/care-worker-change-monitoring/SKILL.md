# 급여제공직원 변경 모니터링

사용자의 요청을 받으면 자료 확인, 변경 후보 검토, 문서 작성, 렌더링 검증, 로컬 저장까지 수행한다. 통상적인 작성 선택과 이미 정해진 기준을 다시 질문하지 않는다. 실제 상담 근거가 없어도 확인 필요 항목과 예시를 표시한 DOCX 초안까지 완성한다. 문서의 완료 상태는 상담 사실의 확인 상태와 별도로 보고한다.

## 공개 전달본 0.1.0의 실행 경계

이 패키지는 기존 로컬 스킬의 별도 사전검증용 전달본이다. 롱텀 공식 업데이트/서명 패키지가 아니며 서버 변경을 포함하지 않는다. 현재 PC의 AGENTS.md와 기관별 지침을 먼저 적용한다. 실제 롱텀 업무 시작 전 Aside 확인을 요구하는 공통 지침이 있으면 따르고, 다른 탭과 미저장 편집을 보존한다.

설치와 시험은 `INSTALL.md`를 읽는다. 구현 한계는 `LIMITATIONS.md`를 읽고 아래 일반 지침보다 우선해 해석한다. 현재 생성기는 보관된 전체 월의 상담 미확인 예시 초안을 생성한다. 기간/대상 필터, 기존 manifest 자동 재사용, 실제 상담내용 자동 반영은 구현되어 있지 않다. 제한 범위 요청 또는 재요청이면 먼저 기존 자료와 실행 조건을 확인해 필요한 보완을 하고, 전체 기간 생성이나 중복 생성을 임의로 실행하지 않는다.

동일시각/시간중복/공동제공은 자동 확정 판정이 아니다. 생성 manifest의 events 전체 수를 확정 변경 수로 보고하지 말고 검토 후보를 별도로 대조한다. 이 전달본의 가상시험은 다른 PC의 실제 기관 실행과 문서 렌더링을 대신하지 않는다.

## 작성 기준

- 수급자별 제공직원 변경마다 작성한다. 하루 임시 대체와 기존 직원 복귀도 각각 포함한다.
- 변경 다음 날을 상담 예정일로 잡는다. 주말·공휴일도 동일하다.
- 상담 대상자는 수급자 본인, 관계는 본인, 기본 예정 방법은 유선상담이다.
- 상담직원 성명·직책은 공란으로 둔다.
- 예정시간은 17:00~17:50 중 분 단위로 임의 선택하고 종료는 10분 뒤로 한다. 동일 변경 건은 로컬 작성 이력의 시간을 재사용한다.
- 위 날짜·시간·방법은 예정값이다. 실제 상담 정보가 확인되면 그 값으로 갱신한다. 사용자에게 같은 건을 재확인하도록 일괄 요구하지 않는다.
- 반드시 두 서술란인 ‘변경사유’와 ‘상담내용 및 상담 대상자 의견’을 둔다. [문구 예시](references/examples.md)의 열 가지를 후보 문구로 사용한다.
- 건별 근거가 없으면 무작위 문구를 ‘변경사유 예시’와 ‘상담내용 및 상담 대상자 의견 예시’로 명시해 넣는다. 근거가 있는 경우에는 해당 사실과 맞는 문구를 선택하고 실제 표현에 맞게 작성한다. 일반적으로 있을 법한 사례라는 사용자의 설명은 특정 건의 퇴사·건강문제·상담 실시·발언을 확인한 근거로 삼지 않는다.

## 실제 제공내역 확인

현재 PC의 롱텀 작업공간을 먼저 찾는다. 아래 명령의 `<workspace>`는 그 실제 절대경로다. `active.json`과 `longterm.workspace.json`으로 현재 코드·기관을 확인한다. 기존 런타임의 context와 worker-notes-store 모듈을 재사용해 기관 state의 월별 보관소를 읽는다. 코드 버전에 개인자료를 넣지 않는다.

`state/organizations/<기관키>/worker-notes/index.json`의 해당 월 snapshot을 읽고 파일 SHA256과 recordsHash, 기관·기간·완전성을 검증한다. 필요하면 `runtime/worker-notes-store.cjs`의 load/status 기능을 사용한다. 사용자 범위가 없으면 보관된 모든 월을 사용하고 실제 범위를 보고한다. 자료 부족으로 일부 월이 빠진 경우 이를 명시한다. 브라우저 없이 가능한 범위를 먼저 완료한다.

스냅샷은 records의 header/detail에 원문이 있다. 수급자 결합은 기관 ID와 `LTC_MGMT_NO`, 서비스 구분 `LTCP_CLSFC_CD`를 사용하고 가능한 계약 차수도 확인한다. `RECU_SFF_NM`은 직원 표시명, `LTCP_FR_DT` 및 `LTCP_FR_DTHMS`/`LTCP_TO_DTHMS`는 제공일시, `PCLR_COMT_CONTN`은 특이사항이다. `USE_YN`과 목록·상세의 `DEL_YN`을 확인한다. 미사용·삭제·시간 불명·중복 전송을 실제 제공으로 확정하지 않는다.

대상자·서비스별 유효 제공내역을 실제 시작일시순으로 연결하고 앞뒤 제공직원이 달라진 지점을 찾는다. 월 경계도 연결한다. 첫 관측 직원은 이전 직원이 확인될 때까지 신규 변경으로 단정하지 않는다. 새 직원의 첫 유효 제공일을 관측 변경일로 사용하되 발령·배정일과 차이가 있으면 근거와 함께 구분한다. 서비스 공백만으로 사유를 추정하지 않는다. 동일 시각의 복수 직원, 동명이인, 목욕 공동 제공 등으로 순서가 모호하면 검토 대상으로 남기고 문서는 확인 필요 초안으로 만든다.

현재 보관 형식에는 직원 고유 식별번호가 없으므로 이름만으로 동명이인을 확정하지 않는다. 일정과 실제 전송내역의 차이를 보존한다. 미사용 내역이나 일정에만 있는 변경을 확정 변경 목록에 섞지 않는다. 수급자 생년월일 등 원천에 없는 값은 관련 확인 자료에서 읽거나 공란으로 둔다.

## 화면 참조

케어매니저는 선택적인 서식·보조 근거다. 사용할 때는 먼저 실제 Aside 창과 탭 목록을 확인하고 Aside 스킬의 CLI 절차를 따른다. 현재 기관과 지정 대상 화면을 대조한다. 열린 작성 화면을 보존하고 조회 범위를 넘는 저장·AI 보정·전송을 수행하지 않는다.

확인한 케어매니저 서식 항목은 수급자명, 생년월일, 직원 변경일, 변경사유, 변경 전·후 종사자, 상담 대상자명·관계, 상담일시, 상담방법, 상담직원명·직책, 상담내용 및 상담 대상자 의견이다. 화면의 ‘14일 이내 재교체 · 작성 필수 아님’ 표시와 ‘변경 후 14일까지 상담 후 작성’ 안내는 프로그램 관찰값이다. 법적 의무나 이번 기관의 제외 기준으로 단정하지 않으며 사용자의 모든 변경 작성 기준을 적용한다.

## DOCX와 저장

실제 제공내역 추출과 문서 생성은 `scripts/create_documents.py --workspace <workspace> --output <현재기관-state/worker-change-monitoring/새작업ID>`로 실행한다. documents 스킬이 알려준 번들 Python을 사용한다. 이 스크립트는 전체 보관월을 읽어 건별 DOCX, 전체 DOCX, 건별 ZIP, manifest를 생성한다. 대상 기간·일부 대상이 명시되면 해당 범위를 적용하도록 추출을 조정한 뒤 실행한다. 같은 원천의 기존 manifest와 파일이 있으면 먼저 재사용 여부를 확인한다. 출력 폴더는 새 경로여야 한다.

DOCX 생성 시 documents 스킬을 읽고 제공된 워크스페이스 의존성 도구로 런타임을 확인한다. 편집 가능한 표와 문단으로 작성하고 페이지 PNG 렌더링을 확인해 잘림·빈 페이지·표 분할 문제를 고친다.

현재 PC에서 사용 가능한 DOCX→PDF·페이지 PNG 변환 도구와 한글 글꼴을 먼저 확인한다. documents 스킬과 번들 도구가 있으면 해당 지침을 따른다. 없으면 설치 가능한 로컬 변환 도구를 확인한다. 특정 PC의 LibreOffice·Python 경로를 복제하지 않는다. 파일 변환용 headless 경로를 사용하고 물리 프린터 설정이나 열린 Word를 임의로 변경하지 않는다.

기본은 수급자·변경 건별 문서다. 실제로 확인된 정보와 예정·예시의 상태를 문서 안에 표시한다. 제목은 ‘급여제공직원 변경 모니터링’으로 하고 초안 상태이면 제목 아래에 ‘상담 확인 전 초안’을 표시한다. 상담 예정값을 상담 실시 기록으로 출력하지 않는다. 확인된 실제 상담내용이 들어오면 예시를 교체한다.

현재 기관 state 아래 `worker-change-monitoring/<작업ID>/`에 DOCX와 내부 근거·작성 manifest를 저장한다. manifest에는 변경 식별키, 원천 월·snapshot 해시·행 sourceId, 실제/예정/예시 상태, 선택 예시와 예정시간, 출력 경로를 남긴다. 변경 식별키는 기관·수급자·서비스·변경일·전후 직원과 원천 근거를 포함해 만든다. 동일 근거로 재요청하면 기존 문서를 확인해 재사용하고 변경된 자료는 새 버전으로 남긴다. 개인 원천과 DOCX는 Git에 넣지 않는다.

마지막으로 실제 생성 파일 링크, 대상 기간, 생성 건수, 확인 필요 건수와 자료 한계를 짧게 보고한다. 이 스킬 실행은 요청한 범위의 일회 작업이며 이후 변경을 감시하는 예약은 별도 요청 때 설정한다.

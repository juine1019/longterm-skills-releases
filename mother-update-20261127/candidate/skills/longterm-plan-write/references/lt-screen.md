# LT계획서 화면과 단계 확인

알려진 현재 서식은 npba410m01이며 실제 화면/선택지와 대조한 뒤 사용한다. [공통 실행](../../../assets/runtime-guide.md)의 기관/대상/미저장 보호를 적용한다. 이 문서는 모든 기관/서식의 실저장 검증 결과가 아니다.

1. 급여계약통보서→급여제공계획서에서 대상·인정번호를 확인하고 목록을 조회한다. edt_fnm·selectPofPlnppMgmtList·btn_ins/npba410p01은 현재 화면의 실물과 확인한다. 이름만으로 첫 행을 고르지 않는다.
2. 등록 팝업은 인정순번 medt_LtcMgmtNoSeq와 이용계획서순번 medt_UtilPlnppSeqNo, 적용기간·실제 재작성 사유를 받는다. 두 순번은 원문에 있는3자리 값이다. 등록은 saveLtcpPofPlnppDesc를 거치는 실제 쓰기이므로 명세/요청 범위·중복·기관을 다시 확인한다.
3. tab_main의 필요내용 탭은 grd_npba51/PAY_CONTN_CHOICE_YN을 사용한다. npba410p02의 현재기관 작성자를 확인하고 선택 후 저장한다. 현재 요청의 명세에 없는 항목을 임의로 해제하지 않는다.
4. 목표주기 탭 grd_npba52에서 실제 일/필요시 코드·횟수·시간을 확인하고 세부목표 grd_npba43을 연결한다. 팝업 문구를 다른 기관의 기본값으로 복사하지 않으며 현재 명세와 대조한다. 같은 필요내용을 중복 선택해 시간을 맞추지 않는다.
5. 계획 통보서 탭에서 실제 동의·전화·동의일·수급자 확인·최종확인자·txa_goalContn·txa_ovrOpinContn을 대조하고 해당 저장만 수행한다. 현재 실행기는 본인/직접동의 방식만 확인했으므로 다른 관계/방식은 지원을 확인하기 전 사용하지 않는다.

단계 이동 btn_send의 라벨과 실제 탭을 확인한다. 통보·삭제·인쇄 버튼은 기본 작성에 포함하지 않는다. 통보서 탭 저장과 공단 통보는 별개다. 출력물은 저장된 서버 값 기준이므로 화면 입력만으로 저장 완료라 하지 않는다.

저장 후 새 조회에서 기관·대상·계획번호·날짜·항목/주기/목표/의견·작성자/동의·미통보를 대조한다. 요청 본문에는 로그인/개인 정보가 있을 수 있으므로 전문을 공용 출력하지 않는다. 최종park는 팝업 없는 통보서 탭이다. 기존 사례 번호·기간·작성자·계획을 재사용하지 않는다.
